# Adding content to Brainy Quest

Every stage has three star tiers (★ Easy, ★★ Medium, ★★★ Hard). Everything is open to play; the `requires` path only drives the "Next" suggestion and what Daily Mix / Speed "Everything I know" draw from.

## Math skill

1. **Generator** in `js/math/skills.js`. Return one of these problem kinds, always with `steps` (a worked solution, kid-friendly):
   - `column` via `makeAdd/makeSub/makeMul(a, b)`; `division` via `makeDivision(a, b)`
   - `input` `{ prompt, answer, steps, answerType?: 'decimal', answerText?, suffix? }`
   - `choice` `{ prompt, choices, answer, steps }` (answer must be in choices, choices unique)
   - `fraction` `{ prompt, answer: { n, d }, steps }` (equivalent answers are accepted)
   Parameterize difficulty (`genX(rng, level)` or option args) instead of copying generators. Use `until(make, ok)` for shape constraints and `rng` everywhere (never `Math.random` inside generators) so tests can seed.
2. **Skill** entry in `SKILLS` with `S(id, unit, title, emoji, requires, desc, gen, { guided?, gym? })`. New topic? Add it to `UNITS` (order = map order). Use a colorful emoji; plain symbols like ➕ render as black icons.
3. **Tiers** in `js/math/tiers.js`: `'<id>': [T(label, gen), T(...), T(...)]`. Labels are short and concrete ("Carry from the tens", "Sums to 10"). The module throws at load if a skill lacks 3 tiers.
4. **Tests** in `tests/math.test.mjs`: every tier is auto-checked for validity; add shape assertions to "star tiers generate exactly the shape each tier promises" (or the basics test) proving ★ < ★★ < ★★★ really differ.
5. Sample real output before trusting it: `node tools/content-review.mjs --skill <id> --show 3` (the `content-review` skill) prints solved samples per tier and flags trivial, repetitive or thin problems.
6. Presentation rules: + and − are written one number below the other (`stacked(a, b, op)`, also set `nums: [a, b], op` so wrong-sign mistakes are diagnosed); Big Numbers use K / M / B symbols (`shortBig`) with the `SYMBOLS` hint line. Steps explain why, not just the arithmetic: say what the idea means, do it, then check it. Steps are plain text (no HTML) and should end calculations with `= result`: the walk-through after a 2nd miss asks the kid for that number. A wrong answer also shows 2 worked examples generated from the same tier (`js/math/examples.js`), so every tier must produce varied problems.
7. Give the skill a grade in `js/math/grades.js` (a unit test fails without one).

## English, Science or Coding unit

All three use the shared lesson engine (`js/lessons/lessonApp.js`, registry in `js/lessons/subjects.js`). Units live in `js/english/content.js`, `js/science/content.js` or `js/coding/content.js`: `U(id, section, title, emoji, [L(title, html), ...], questions)`. New section? Add it to `ENGLISH_SECTIONS` (order = page order).
- At least 7 questions (Expert asks all, Warm-up asks 6, Quiz asks 8).
- `mc`: `{ t:'mc', q, c:[...], a, e }`. The Warm-up keeps the answer plus one random wrong choice, so every wrong choice must be plausible on its own.
- `tap`: `{ t:'tap', q, s, a:[words], e }`. Each answer word must appear exactly once in `s`.
- `fill`: `{ t:'fill', q, s:'... ___ ...', a:[accepted answers], e }`. Warm-up hints "It starts with x", so put the most natural answer first.
- Original content only, short sentences, kid-friendly explanations in `e`.
- Coding questions may add `code: '...'` (plain text, shown as an indented code block; keep lines at most 32 characters so they fit a phone). Run every Python snippet to confirm the stated output.
- Source books (study guides) are only a topic checklist: write every lesson, example and question yourself, and never commit the books.
- A new lesson subject is one entry in `js/lessons/subjects.js` plus its id in `js/lessons/ids.js`.

## Spelling list

In `js/spelling/words.js`: an array of `[word, part of speech, definition, sentence]`, then an entry in `BUILTIN_LISTS` (`id`, `name`, `emoji`, `group`, `builtin: true`, `words: toWords(...)`). Starter lists come first.
- The definition must not contain the word. Sentences use the word naturally.
- Lists split into easy/medium/hard thirds automatically (`splitTiers` in `js/spelling/logic.js`).
- `js/spelling/woc2024.js` is generated by `tools/build-woc.py`; never edit it by hand.

## Finish

- `node --test tests/*.test.mjs` and `node tools/content-review.mjs` must pass (no ERROR lines).
- Check the new content in the browser at phone and desktop size (the `regression-test` skill), then update the README feature table if counts or sections changed.
- No em dash characters anywhere; use a hyphen.
